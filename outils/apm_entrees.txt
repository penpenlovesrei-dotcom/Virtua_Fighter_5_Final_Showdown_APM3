# LA DISPOSITION (rappel ; elle est compilee dans le stub)
#
#   CLAVIER                      MANETTE
#   fleches      directions      croix directionnelle / stick gauche
#   Entree       VALIDER         START, et A
#   W            ANNULER         B
#   X            P               A
#   C            K               B
#   V            G (la garde)    X
#   Q            le 4e bouton    Y        -- le jeu l affiche "NO USE"
#   Espace       piece           BACK
#   F1 / F2      TEST / SERVICE
#   Echap        quitter le mode courant (aussi BACK a la manette)
#
# LB, RB, LT, RT NE FONT RIEN, et ce n est pas un choix -- voir plus bas.
#
# EN MODE ARCADE (ram\mode.txt = arcade), la MANETTE change sur trois lignes :
#   bouton menu       START
#   bouton affichage  TEST     -- il n'est alors plus SELECT ni la sortie
#   bouton XBOX       SERVICE
# Le clavier ne change pas : Entree, Espace, Echap, F1 et F2 gardent leurs
# roles. BACK est retire des codes 6 et 15 parce qu'un masque est un ACCORD :
# trois roles sur un bouton s'additionneraient au lieu de se choisir.
# Le bouton XBOX n'arrive que par XInputGetStateEx (l'export sans nom
# d'ordinal 100 de xinput1_4) ; le journal dit a chaque lancement s'il est
# lisible -- la ligne " PAD    XInputGetStateEx ... ".
#
# POURQUOI LE L2 ET LE R2 NE SE CABLENT PAS -- mesure du 2026-10-10,
# tools/entrees.py, sur CE build. La chaine va de la touche au code que
# l interface lit, en trois etages :
#
#   code apm   bit du masque arcade   code logique   role
#      7              0                     7        VALIDER
#      8              1                     8        VALIDER (annuler)
#     12              2                     7        VALIDER
#     11              3                     9        VALIDER
#      9              6                   100        COMBAT  -- P
#     10              7                   102        COMBAT  -- K
#     13              4                   103        COMBAT  -- G
#     14              5                   101        COMBAT  -- le quatrieme
#
# IL N Y A QUE QUATRE BOUTONS D ACTION, et le jeu lui-meme n en emploie que
# TROIS : son ecran OPTIONS > Controls affiche P sur la croix, K sur le rond,
# G sur le carre, et NO USE sur le triangle. Les codes 8, 11 et 12 ne font que
# valider.
#
# Les boutons L1, L2, R1, R2 existent bien dans le jeu d ORIGINE : la version
# console a sa propre couche d entrees. Ici, le masque arcade que compose
# 0x180243ED0 ne porte que douze bits, et ses bits 8, 10 et 11 ne sont produits
# par AUCUN code d entree -- le modele APM3 n a pas de quoi les alimenter.
# L ecran Controls le dit lui-meme : toutes ses lignes de gachette sont
# " NO USE ". Il n y a donc rien a quoi les brancher.
#
# " touche2 <code> = <nom> " donne une SECONDE touche a un code, comme
# " bouton2 " pour la manette : de quoi faire doubler un code par un autre
# bouton si on le veut.
#
# Dans les menus, le moteur ne lit que DEUX codes : le 7 (Entree / START)
# pour valider, le 8 (W / X) pour annuler. Voir analysis/carte_options.md
# section 6. Le bouton A n'y fait donc rien par defaut ; pour qu'il valide :
#     nom valider = 7
#     bouton valider = a
# Attention, un masque a PLUSIEURS boutons est un ACCORD, pas une
# alternative : `(etat & masque) == masque`. On ne peut donc pas mettre
# START et A sur le meme code pour qu'ils vaillent l'un ou l'autre.
#
# D'OU LE SECOND MASQUE (2026-10-04) : " bouton2 <code> = <nom> " donne un
# DEUXIEME bouton au meme code, combine par OU. C'est lui qui regle le defaut
# signale -- " a la manette les boutons ne sont pas reconnus, seul le bouton
# start fonctionne ". C'etait vrai : les menus ne lisent QUE le code 7 et le
# code 8, et A ne portait aucun des deux. La disposition compilee pose donc
# maintenant, par defaut :
#     bouton2 7 = a            A valide, comme START
#     bouton2 8 = b            B annule, comme X
# A garde aussi le code 9 (la croix, en combat) : presser A envoie donc les
# codes 7 ET 9. En combat le code 7 n'est lu par personne, c'est sans effet ;
# c'est dit plutot que cache.
