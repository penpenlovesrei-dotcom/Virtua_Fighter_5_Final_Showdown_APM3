# LE PROGRAMME `water_ring`, DES DEUX COTES
#
# Releve direct dans les archives, sans passer par une note :
#
#   Xbox 360 : `SOURCES/X360_VF5/media/shader_hlsl_88.farc`. Chaque .fp/.vp
#   est un en-tete SEGA de 0x28 octets, puis une CTAB D3DX gros-boutiste
#   (taille 0x1C, version 0xFFFF0300 = ps_3_0), puis le microcode Xenos.
#   La CTAB nomme les parametres et donne leur registre : c est elle qui
#   est lue ici, pas le microcode.
#
#   APM3 : `w64/shader_pxd_w64.farc`. Conteneur GSPS/GSVS, DXBC a +0x80.
#   Les DXBC sont DEPOUILLES (pas de chunk RDEF) : les liaisons se lisent
#   dans les declarations `dcl_resource` du flot SHEX.
#
# CE QUE LE MICROCODE XENOS N A PAS ETE : DESASSEMBLE. On ne compare donc
# pas le calcul instruction par instruction, seulement ce que chaque
# programme DECLARE lire. C est suffisant pour la question posee -- u3 et u4
# sont declarees des deux cotes ou elles ne le sont pas -- mais ce n est pas
# une lecture du calcul.
#
# Depose le 2026-11-19 pour `analysis/eau_ring_eileen.md`.
# Les adresses X360 sont celles de `extracted/X360_VF5/vf5_x360.img`
# (Virtua Fighter 5, Xbox 360, 2007, base 0x82000000) -- PAS celles de
# `X360_FS`, qui est Final Showdown et repondrait autre chose sans
# erreur. Les adresses APM3 sont celles de
# `binaires/vf5fs-pxd-w64-Retail_APM3.dll.origine`, base 0x180000000.
